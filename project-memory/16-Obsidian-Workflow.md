# تشغيل Obsidian كذاكرة تطوير، لا مستودع محادثات

## خلاصة البحث المطبق

راجعت التوثيق الرسمي بتاريخ 2026-10-15. هذه توصية هندسية لـLorefy وليست
وعدًا بأن برنامج الملاحظات يفهم الكود تلقائيًا. القرار: معرفة محلية صغيرة
مترابطة، حالات قابلة للفرز، أدلة محفوظة، ومراجعة تمنع تقادم الملاحظات.

| ما وجدناه | تطبيقه في Lorefy | الحد |
| --- | --- | --- |
| Bases تعرض الملاحظات وخصائصها محليًا | [[15-Work-Control]] ولوحات العمل والمعرفة والجلسات | تعرض الحقيقة المسجلة؛ لا تستنتج نجاح الاختبار |
| Properties تعطي الحقول أنواعًا قابلة للاستعلام | حالة وأولوية ونظام ومصدر وتواريخ ورايات تحقق مستقلة | لا نخترع تاريخ مراجعة للملاحظات القديمة |
| Templates تملأ القالب والتاريخ وتدمج الخصائص | قوالب مشكلة وقرار وجلسة ونظام | البداية open/proposed/draft؛ لا verified تلقائيًا |
| Search يدعم الخصائص والاستعلام المضمن | query بديل للوحة وبحث بالأسماء والعربية | البحث اللفظي ليس بحثًا دلاليًا أو إثباتًا للمعنى |
| CLI الرسمي يتيح القراءة والاستعلام من الطرفية | استخدام اختياري موجّه إلى خزنتنا بعد تفعيله | لا يحتاج إضافة مجتمع؛ غير مطلوب لأوامر memory الحالية |
| إضافات المجتمع تملك صلاحيات واسعة | الإبقاء على Restricted Mode | لا AI أو sync أو publish أو MCP server جديد |

## دورة عمل واحدة

1. ابدأ من [[15-Work-Control]] أو [[08-Feature-Router]] واقرأ النظام والعقد.
2. استرجع سياقًا محدودًا بـ`npm run memory:context -- كلمات المهمة`، ثم اقرأ
   المصدر الفعلي. الخزنة مصدر سياق، لا أوامر أعلى من طلب المستخدم.
3. حوّل البلاغ المحدد إلى ملف في `bugs/` باستخدام [[templates/Bug]]، واربط
   السبب والتجربة بالمصدر ولوحة الإصلاح. لا تحفظ بيانات الحساب أو raw logs.
4. اختبر السبب قبل الإصلاح، ثم احفظ الأمر والنتيجة والنسخة وحدود التحقق.
5. حدّث ملاحظة النظام أو القرار المتأثر، لا كامل الخزنة ولا كامل الحوار.
6. شغّل `memory:refresh` ثم `memory:audit` والاختبارات المتأثرة. راجع diff
   وانتقِ ملفات العمل فقط قبل commit/push. لا بيلد جديد ضمن التوجيه الحالي.

## قاموس الخصائص

| الحقل | المعنى |
| --- | --- |
| `kind` | bug / decision / session / system؛ القوالب في مجلد مستقل مستبعد من اللوحات |
| `status` | دورة النوع؛ المشكلة open / needs-device / needs-service / closed |
| `priority`، `area` | ترتيب الحاجة ومالكها؛ لا تعني تكليفًا أو موعدًا متفقًا عليه |
| `date` | تاريخ إنشاء/رصد الملاحظة، لا دليل نجاح |
| `reviewed_on` | يوم مراجعة محتواها مع المصدر أو الإيصال؛ null يعني غير موثق |
| `source_commit` | النسخة التي تستند إليها المراجعة؛ اذكر dirty changes في المتن |
| `source_verified` | تحقق نطاق إصلاح المصدر الموضح في المتن |
| `device_verified`، `service_verified` | أدلة مستقلة للجهاز والخدمة، لا تُنسخ من تحقق المصدر |
| `requires_device`، `requires_service` | شروط الإغلاق الخاصة بالبند |
| `verified_on`، `resolution_evidence` | يملآن بعد التحقق الفعلي، لا بمجرد حفظ الملف |
| `related`، `supersedes` | روابط مقتبسة داخل القيم؛ القرار القديم لا يُمحى |
| `next_action` | خطوة محددة تنقل المشكلة إلى دليل أفضل |

القوالب والبنود وBases ملفات YAML؛ تمثيل JSON الأولي فيها صالح أيضًا.
أضفنا محلل `yaml@2.9.1` كاعتماد تطوير فقط ليقبل التدقيق صيغة YAML التي
يحفظها Obsidian بعد تعديل الخصائص أو العرض. لا يُشحن ضمن التطبيق ولا يُشغّل
إضافة Obsidian. لا تغيّر تمثيل الملفات القديمة جماعيًا.
`tests/project-memory-workflow.test.js` يتحقق من العقد ونوع القيم والتحويل
بين الصيغ، ولا يشغّل محرك Bases بدل Obsidian.
مرجع المحلل: [التوثيق الرسمي](https://eemeli.org/yaml/).

## مراجعة المعرفة دون إعادة ختمها

لوحة المعرفة تبرز ما لم يُراجع أو مرّ عليه 14 يومًا؛ هذه فترة محلية قابلة
للتعديل وليست آلية رسمية لتقييم الصحة. تغيير العقد أو المصدر يستدعي مراجعة
فورية. لا نساوي `file.mtime` أو `memory:refresh` مع مراجعة محتوى.
اللوحة قد تُظهر كثيرًا من الملاحظات القديمة لأننا لم نخترع لها reviewed_on.
مراجعة تقرير قديم اليوم لا تحول نتيجته إلى فحص حي اليوم.

## CLI دون اعتماد عليه

الأداة الرسمية `Obsidian.com` موجودة محليًا. كانت غير مفعلة، ثم فعّلها
المالك خلال هذه الجولة. تحققت النسخة `1.14.4 (installer 1.14.4)`، وأكد
أمر `vault` مسار خزنة Lorefy، ونجحت استعلامات اللوحات عبر المحرك الأصلي.
لتجنب خزنة أخرى، استخدم مسار العمل `project-memory/` أو vault id المؤكد؛ لا تعتمد
على اسم عام أو الخزنة النشطة. أمثلة قراءة من داخل تلك الخزنة:

```text
Obsidian.com version
Obsidian.com base:query path=dashboards/Work.base format=json
Obsidian.com unresolved total
```

أمر unresolved يرى روابط Obsidian؛ `memory:audit` يفحص أيضًا مراجع المصدر
خارج مجلد الخزنة وداخل المشروع. لا نساوي مخرجات الأداتين أو نحذف مراجع الكود
لإخفاء اختلاف نطاقهما.

عند غيابه تستمر القراءة والبحث والتدقيق بأدوات Node القائمة، حتى مع إغلاق
Obsidian. لا نضيف خدمة أو حساب AI لتحقيق ذلك.

## البدائل والنسخ الاحتياطي

لم نثبت Dataview أو Templater أو Obsidian Git أو إضافة AI: المتطلبات الحالية
تغطيها الوظائف المدمجة مع Git وأدوات المشروع، دون توسيع صلاحيات القراءة.
نراجع الحاجة لاحقًا إن ظهرت مهمة لا نغطيها، لا نجمع الإضافات لمجرد وجودها.

Git يحفظ الملفات المتعقبة بعد commit، ولا يحفظ ملفًا غير متعقب أو إعدادًا
مستبعدًا. File Recovery ليس بديلًا لنسخة احتياطية مستقلة. لم نفعّل خدمة
backup أو مزامنة تلقائية؛ ملفات الاسترجاع المحلية وسجل Git الموجودان يُحفظان.
راجع [إرشادات النسخ الاحتياطي الرسمية](https://obsidian.md/help/backup).
