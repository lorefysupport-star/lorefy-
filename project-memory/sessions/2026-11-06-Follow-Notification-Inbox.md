# إشعار المتابعة لا يظهر في الصندوق

البلاغ: وصل إشعار متابعة على iOS، لكن صفحة الإشعارات داخل Lorefy بقيت على
«لا إشعارات بعد» سواء فُتحت من الرئيسية أو الملف الشخصي.

فحص المصدر أظهر أن `renderCloudNotifications` يعيد عرض الذاكرة، لكن الصفحة
لا تجلب بيانات backend عند تركيبها؛ الجلب كان مربوطًا بزر الجرس/الاستيقاظ/
الدورية/Push. هذا يترك فجوة إذا فاتت realtime insert أثناء اتصال متقطع.
إضافة اختبار يركّب الصفحة دون النقر على الجرس ويزوّد backend بإشعار متابعة
أثبتت الخلل: فشل `assert.ok(inbox)` قبل التغيير.

أُضيف تتبع لعقدة صفحة الإشعارات؛ عند تركيب عقدة جديدة يعاد العرض ثم يستدعى
`refreshCloudNotifications()`. إعادة العرض اللاحقة على نفس العقدة لا تطلق
جلبًا آخر، وإزالة الصفحة تعيد حالة التتبع لتعمل عند فتحها لاحقًا. نطاق
المستخدم والمقاومة للاستجابات المتأخرة في backend بقيت كما هي.

تم تحديث إصدار cache لمصدر runtime في `index.html` و`sw.js`، ونسخ الملفات
الثلاثة المتأثرة فقط (`index.html`, `sw.js`, runtime) إلى `ios-web` و
`ios/App/App/public`. جميع نسخ iOS طابقت المصدر بـSHA-256.

الاختبارات بعد الإصلاح: 58/58 عبر مجموعات backend/runtime/navigation/links.
لم يُشغّل build أو TestFlight. لا صلاحية قراءة إنتاج Supabase في هذه الجولة؛
لا نعرف من المصدر وحده هل الإشعار الذي وصل للهاتف مسجل للحساب الحالي أم لا.
بعد وصول نسخة جديدة، فتح صندوق الإشعارات يعيد الجلب. إذا بقي فارغًا رغم ذلك،
فالخطوة التالية فحص `notifications` وRLS/trigger الحي read-only، لا كتابة سجل يدوي.
