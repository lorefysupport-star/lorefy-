# Lorefy UI consistency audit - 2026-09-25

## Scope and method

- Inspected the local demo at home, community, search, library, and profile routes.
- Opened a work detail, post composer, attachment picker, conversation thread, and settings sheet.
- Checked light and dark appearances, visible control names, touch sizes, and page width at 375x812 and 768x1024 browser viewports.
- Used the existing Superdesign theme as the visual baseline: blue action accent, quiet surfaces, Readex Pro/Cairo, and Lucide controls.

## Confirmed differences and changes

| Area | Observed difference | Resolution |
| --- | --- | --- |
| Global controls | Legacy purple variables still colored community filters while the navigation used blue. | Mapped legacy accent aliases to the active blue token in both appearances. |
| Supporting text | Several light-theme muted tokens used low-contrast gray. | Aligned secondary and tertiary labels to the darker supporting-text token. |
| Suggested people | Search icon had no accessible name. | Named the control and verified it in the rendered page. |
| Conversation | Reply field floated above unused space when a thread was short. | Let the thread body grow and anchored the composer at the bottom. |
| Conversation rows | Nested tinted post cards conflicted with the continuous thread layout. | Removed card framing within the thread while retaining separators. |
| Work detail | Character actions used a star glyph and a chess glyph. | Replaced both with Lucide icons and verified that both SVGs render. |
| Settings | Legacy inline styling left purple-tinted icon backgrounds beside blue icons. | Aligned those settings icon backgrounds with the blue accent surface. |

## Verification and limits

- After loading, the five main routes had no visible unnamed buttons and no controls below 40px in the tested demo viewports. No document-level horizontal overflow was found at 375px.
- No legacy purple button background remained visible on those five routes in light mode. Dark-mode control accent was blue.
- At 768px, demo preview kept the app inside an approximately 426px phone frame. This does not validate native iPad layout.
- This audit is not an exhaustive click-through of every conditional screen, authenticated account state, or native iOS device. Those require device and live-account QA before claiming complete UI coverage.
