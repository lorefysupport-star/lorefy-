# الاستفادة من Supabase Pro في Lorefy

فحص 30 أكتوبر 2026. المشروع `qsroxmltioxqozmykens`، منظمة `lorefy`.
المصدر الأساسي عند البدء `5933fdc`. هذا التقرير يميز ما يعمل، وما تغير محليًا،
وما يحتاج تنفيذًا واختبارًا آخر. الاشتراك لا يصلح أخطاء التطبيق تلقائيًا، ولا
يجعل كل إضافة مدفوعة مشمولة. لم نغير الفوترة أو الأسرار أو صلاحيات المستخدمين.

## الحالة المثبتة الآن

- لوحة Billing تعرض **Pro** و**Spend cap enabled**. أبقينا الحد دون تغيير.
- دورة الاستخدام المعروضة: 29 أكتوبر إلى 29 نوفمبر. القراءة لقطة وليست توقعًا
  شهريًا؛ بعض العدادات تتأخر ساعة أو 24 ساعة.
- Egress: **0.092 / 250 GB**، وCached Egress: **0.016 / 250 GB**.
- Storage: **0.029 / 100 GB**، وEdge Functions: **573 / 2,000,000**.
- Realtime: ذروة **1 / 500** ورسائل **1 / 5,000,000** في الدورة المعروضة.
- MAU: **1 / 100,000**. Image Transformations: **0 / 100**. ليست أعداد كل
  الحسابات المسجلة؛ الدورة الجديدة قصيرة وعداد MAU يتأخر.
- مشروع `ACTIVE_HEALTHY`، Postgres 17؛ حجم قاعدة البيانات نحو **26.1 MiB**،
  و7 اتصالات، وصفر انتظار أقفال وقت القراءة. هذه ليست قياسات CPU أو حمل ذروة.
- Buckets الثلاثة `profile-media` و`review-media` و`custom-covers` **خاصة**.
  حدود الرفع الحالية 5/8/5 MiB وصيغ JPEG/PNG/WebP بقيت كما هي.
- publication التحديث المباشر تشمل المراجعات وتفاعلاتها وتعليقاتها، المتابعات،
  الإشعارات والمنشورات وتفاعلاتها. Community يشترك بقناة مشتركة قائمة بالفعل؛
  لم نضف قناة لكل بطاقة ولم نوسع الوصول لتفعيل الميزة.
- ظهرت نسخ PHYSICAL فعلية في Backups؛ أحدث المعروض **29 أكتوبر 22:54:36
  بتوقيت الرياض**. لم ننفذ Restore أو ننزل بيانات الحسابات.

## التحسين المنفذ في هذه الجولة

في نافذة السجلات الافتراضية السابقة البالغة24 ساعة، أعادت Storage **1051**
عملية توقيع ناجحة بمتوسط92.4ms، مقابل112 طلب قراءة موقّع ناجح بمتوسط55.2ms.
هذه أعداد سجلات خدمة وليست حسابًا كاملًا للـCDN أو الباندويث ولا تثبت سبب كل طلب.
المصدر نفسه كان يعيد توقيع الصورة عند كل ظهور لها في المجتمع أو البروفايل.

Smart CDN يعمل تلقائيًا في Pro، لكن كل توكن مختلف للصورة الخاصة ينشئ مفتاح
كاش مختلفًا. لذلك عُدّل المساعد المشترك بدل تغيير هوية الصور أو جعلها عامة:

- [Backend](../backend/lorefy-backend.js): دمج طلبات توقيع الصورة المتزامنة،
  وإعادة استخدام الرابط نفسه في الذاكرة لمدة أقصاها60 ثانية، تنتهي قبل صلاحية
  الرابط بخمس ثوانٍ على الأقل. حد256 مدخلًا، دون localStorage أو خدمة جديدة.
- ما زالت كل قراءة تتحقق من جلسة Auth، حتى إذا وجدت الرابط في الكاش. الكاش
  معزول بالمالك والمالك المحلي والعميل والجيل ومشروع Supabase والبكت والمسار
  وعمر التوقيع. كل مستهلك يرفض النتيجة المتأخرة بعد تغيير الجلسة.
- الخروج/إبطال الجلسة يستبعد الكاش، واستبدال صورة البروفايل أو حذف صور المراجعة
  يبطله قبل الطلب وبعد نجاحه. توقيع بدأ قبل الرفع لا يعيد إدخال نتيجته في الكاش.
- أخطاء الشبكة والصلاحيات والتوقيع الفارغ لا تُحفظ، وتظل المحاولة التالية ممكنة.
- لم نمدد أعمار التوقيع الأصلية، ولم نغير RLS أو الخصوصية أو مسارات الملفات
  أو Cache-Control الخاص بالصور المتغيرة. الروابط الموقعة القائمة ليست آلية
  سحب صلاحية فورية؛ هذا حد موجود قبل التحسين، وليس ادعاء إبطال CDN آني.
- مزامنة انتقائية للملفات الثلاثة Backend/index/sw إلى نسختي runtime فقط؛
  cache `lorefy-v639-storage-reuse`. لا بناء iOS ولا تسليم للمستخدمين الحاليين.

اختبار السلوك نفسه قبل التصحيح سجل20 طلب توقيع لـ20 مستهلكًا متزامنًا، وبعده
**طلبًا واحدًا** لنفس المستهلكين والرابط. هذه نتيجة معزولة لتكرار التوقيع،
وليست ادعاء تحسن التطبيق كله95% أو انخفاض الفاتورة بهذه النسبة.

الاختبارات الجديدة: [storage-signing-cache](../tests/storage-signing-cache.test.js)
تشمل انتهاء الكاش، عزل المشاريع والحسابات، الاستجابة المتأخرة، إعادة المحاولة،
الرفع والحذف والخروج والجلسة المنتهية والحد الأقصى للذاكرة. سجل التحقق النهائي
في [جلسة الجولة](../project-memory/sessions/2026-10-30-Supabase-Pro-Adoption.md).
النتيجة النهائية بعد مزامنة نسخ الويب: **3004/3004 اختبار ناجح، صفر فشل**.
فحص syntax و`git diff --check` ناجحان. هذه ليست شهادة إنتاج أو جهاز حقيقي.

## خريطة استغلال الخدمات

| الخدمة | فائدة Lorefy | الحالة والقرار |
| --- | --- | --- |
| Smart CDN | صور أسرع وتكرار أقل لطلبات المصدر | تلقائي في Pro؛ أصلحنا إعادة استخدام الروابط الخاصة محليًا. قياس cache-hit فعلي بعد التسليم ما زال مطلوبًا. |
| Image Transformations | أحجام مناسبة للأفاتار والغلاف بدل تحميل الأصل | متاح في Pro، لكن100 أصل فقط ضمن الحصة؛ لا نشغله عشوائيًا على كل الصور. المرحلة التالية مقاسات قليلة مع fallback للأصل وقياس الحصة. |
| مساحة Storage والباندويث | استيعاب الصور والزيارات | الحصص الجديدة مؤكدة. لا نرفع حد الملفات لمجرد توفر مساحة؛ ضغط الرفع والتحميل الكسول يظلان مهمين. |
| النسخ اليومية | حماية القراءة والمراجعات والحسابات | نسخ فعلية مؤكدة؛ خطة استرجاع مع اختبار خارج الإنتاج لازمة. النسخة لا تشمل بايتات Storage. |
| مراقبة7 أيام | تتبع انقطاع الدخول والأخطاء بدل التخمين | السجلات والمستشارون استُخدموا الآن. مطلوب خط أساس أسبوعي وتنبيهات محددة، لا جمع بيانات شخصية أو استعلام سجلات بلا حدود. |
| Metrics API | مراقبة CPU/IO والاتصالات وWAL | خيار مراقبة مفيد؛ لا نضع مفاتيحه في التطبيق. ربط وجهة مراقبة وإرسال telemetry يحتاج اختيارًا وموافقة منفصلة. |
| Realtime | تحديث الجرس والمجتمع دون تحميل دائم | الجداول منشورة والقناة المشتركة موجودة. اختبار قطع/عودة الاتصال وجهازين وحسابين يسبق زيادة عدد القنوات. |
| Edge Functions | كاش للكتالوج وحدود طلبات وحماية مفاتيح المصادر |6 دوال ACTIVE مؤكدة؛ لا نكرر التحسينات المنشورة في29 أكتوبر. نحتاج تتبع latency/429/502 لكل مزود. |
| Postgres والفهارس | صفحات ومراجعات أسرع | تحسين29 أكتوبر مطبق؛ لم نعد تطبيقه. لا زيادة Compute من لقطة26MiB/7 اتصالات فقط. |
| Connection pooling | تقليل ضغط اتصالات الخادم | إعداد مناسب للخدمات التي تتصل مباشرة بقاعدة البيانات، لا تبديل REST في تطبيق الهاتف دون سبب. |
| Auth protection | استقرار الدخول وحماية الحساب | لا نفعّل جلسة واحدة أو مهلة قصيرة لأنها تطرد المستخدمين. حماية كلمات المرور المسربة تفيد حسابات كلمة المرور؛ التدفق الحالي Apple/Google يحتاج فحصه الخاص. |
| البريد والهوية | رسائل دخول واضحة باسم Lorefy | إزالة branding متاحة بالخطة؛ إعداد SMTP والنطاق وقوالب البريد مشروط باستخدام فعلي وبيانات المرسل، وليس شرطًا لتدفق OAuth. |
| الدعم بالبريد | تصعيد مشاكل منصة مثبتة | نستخدمه عند مشكلة مستمرة مع أوقات وrequest IDs منقحة، لا نرسل مفاتيح أو بيانات القراء. لم نفتح تذكرة من تلقائنا. |
| Cron | تحديث مجدول للكتالوج وملخصات/تنظيف محدود | إضافة Postgres عامة، ليست حصرية لـPro؛ pg_cron غير مثبت وقت الجرد. لا وظيفة دورية أو حذف تلقائي بلا سياسة وميزانية. |
| Queues | إعادة محاولات الاستيراد/الإشعارات بلا تعطيل الواجهة | pgmq غير مثبت؛ يتطلب تصميم idempotency ومحاولات محدودة ومراجعة سجل الإرسال، لا ضمان وصول APNs لمجرد وجود queue. |
| Full-text/trigram | بحث عن عناوين/مؤلفين محفوظين محليًا بالخادم | قدرة Postgres وليست فائدة مدفوعة حصرية. جرد الكتالوج وتطبيع العربية/الإنجليزية قبل ترحيل البحث. APIs الخارجية لا تصبح مكتبة كاملة بالاشتراك. |
| Vector/AI | توصيات أو بحث دلالي لاحقًا | ليس أولوية الآن؛ يحتاج بيانات وembeddings وتكلفة/خصوصية مستقلة. vector غير مثبت وقت الجرد. |
| GraphQL/Webhooks/Vault | تكاملات خادم عند وجود حاجة | ليست أهدافًا بذاتها؛ نحتفظ بالمفاتيح بالخادم ولا نكرر API موجودًا أو نضيف webhook لكل حدث. |
| Branching / PITR / Custom Domain / Log Drains / Phone MFA / Pipelines | اختبار مستقل أو استعادة أدق أو تكاملات خاصة | إضافات أو استهلاك منفصل؛ لا تفعيل أو إنشاء موارد دون تسعير وموافقة محددة. |

هذه خريطة استخدام عملية وليست تفعيلًا لكل منتجات Supabase، ولا وعدًا بأن Pro
يمنح ميزات Team مثل صلاحيات المشروع التفصيلية أو SLA مؤسسيًا.

## ترتيب التنفيذ المتبقي ومعايير القبول

1. **قبول الصور المحسنة:** تشغيل هذا المصدر في سياق اختبار معزول، قياس الطلبات
   المتكررة والـcache-hit على روابط حقيقية مصرح بها، تغيير صورة ثم العودة من
   الخلفية، وفحص حسابين. لا حفظ توكنات في الأدلة.
2. **صور متجاوبة:** أحجام أفاتار160/320، غلاف320/640، بانر960 كبداية تخضع
   لقياس الشاشات الفعلية؛ contain للغلاف دون قص، والفشل يعيد الأصل. موافقة
   محددة على تجاوز100 أصل قبل توسيع التحويلات، وإلا نبقيها غير مفعلة.
3. **الجرس والمجتمع:** اختبار realtime مع انقطاع/استئناف، dedup بالـID، pagination
   وأحداث read/update. الإشعار المحفوظ ليس مجرد toast. لا رسائل اختبار لأشخاص
   دون موافقة، ولا مسح inbox لتخفيف الحمل.
4. **استيراد متين:** jobs مملوكة للحساب، مفتاح idempotency، checkpoint، retry
   محدود وواجهة تقدم. فصل استيراد المراجعات عن إعادة نشرها كي لا تنتج منشورات
   مكررة. تصميم queue محلي أولًا؛ لا إنشاء جدول إنتاج تلقائيًا.
5. **حماية واسترجاع:** مراجعة RPCs المعلمة من المستشارين واحدة واحدة مع فحوص
   خصوصية/حظر؛ نسخ Storage مشفر إلى وجهة يختارها المالك؛ تجربة restore على
   بيئة معزولة فقط. لا نشر الصور كبكت عام ولا تعطيل RPCs لمجرد إزالة التنبيه.
6. **مراقبة تكلفة وأداء:** متابعة75/90% للحصص وإنذارات فشل Auth وStorage
   وEdge؛ جلب خط أساس7 أيام قبل التفكير في Compute. هذه thresholds مقترحة،
   لم تُنشأ كتنبيهات تعمل بالخلفية في هذه الجولة.

## ملاحظات غير مغلقة

- نافذة24 ساعة تشمل402 سابقة في `lorefy-public`، و20 سجل503 في
  `apple-authorization`، و502/429 من بوابة الكتالوج. لا تعني هذه الأعداد أن
  الانقطاع مستمر الآن. مصدر Apple يعيد503 عند نقص التهيئة؛ لم نقرأ قيم أسراره
  أو نجرب حساب مستخدم، ولا يصح تغييرها اعتمادًا على سجل تجميعي فقط.
- المستشار الأمني أعاد4 ملاحظات RLS بلا سياسات، وpg_net فيpublic، و20 RPC
  من SECURITY DEFINER قابلة لاستدعاءauthenticated، وتعطيل حماية كلمات المرور
  المسربة. الملاحظات لا تثبت ثغرة في كلRPC؛ الجداول الخادمية قد تكون مقصودة
  بلا سياسات عميل. [إرشاد المراجعة](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable).
- مستشار الأداء أعاد ملاحظات فهارس غير مستخدمة/جدول أرشيفي بلاPK وتخصيصAuth
  ثابت10 اتصالات. لم نحذف فهارس أو أرشيفًا ولم نعدلAuth دون قياس.
- مراجع بقية التنبيهات: [RLS بلا سياسة](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)،
  [مكان الإضافة](https://supabase.com/docs/guides/database/database-linter?lint=0014_extension_in_public)،
  [كلمات المرور المسربة](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)،
  [PK](https://supabase.com/docs/guides/database/database-linter?lint=0004_no_primary_key)،
  [الفهارس غير المستخدمة](https://supabase.com/docs/guides/database/database-linter?lint=0005_unused_index)،
  [تخصيصAuth](https://supabase.com/docs/guides/deployment/going-into-prod).
- لا CPU profile، أو اختبار حمل، أو وصول حسابين حقيقيين، أو push/device proof،
  أو تجربة استرجاع. لا ادعاء بأن كل مشاكل التطبيق أُغلقت.
- كل تغييرات الكود محلية؛ لا GitHub أو نشر Edge/SQL أو native build أو Apple.
