# المكتبة: التنظيم والاستجابة بعد دراسة Lootd

التاريخ: 11 نوفمبر 2026. نقطة البداية: `64000e2`.
نطاق العمل: المكتبة في المصدر والمعاينة، دون بيلد أو تعديل خدمات أو بيانات قراءة.

## المرجع الذي اختبرناه

بدأت [مكتبة Lootd](https://www.lootd.app/library) بطلب تسجيل الدخول. بعد أن سجل
المالك دخوله، اختُبرت قراءة الواجهة والبحث وفلترة الحالة وفتح سجل عمل والرجوع فقط.
لم نحفظ أي تغيير أو تقييم هناك، ولم ننقل محتوى الحساب الشخصي إلى هذا التقرير.

- العنوان وإضافة عمل وفلاتر الحالات والبحث تسبق شبكة الأغلفة، دون زخرفة تعيق المهمة.
- المفضلة وحالة العمل والتقييم حقائق مستقلة؛ نموذج العمل يوضح هذا الفصل.
- البحث يُرسل بزر Search، وتغيير الحالة يعرض حالة Loading ثم النتائج.
- البطاقات تصل إلى سجل العمل، ويعرض المرجع التقييم المحفوظ حين يوجد.

نأخذ وضوح التنظيم والفصل بين البيانات والتغذية الراجعة. لا نستبدل البحث المحلي
الفوري بطلب شبكة لكل حرف، ولا ننسخ تقييد عدد المفضلة أو سلم التقييم أو هوية Lootd.
لم نختبر مكتبة ضخمة هناك، ولا ندّعي معرفة تخزينه الداخلي أو تفوق سرعة مقاسًا عليه.

احتياطيًا إذا غاب الموديول. لا اعتماديات أو فهرس بحث أو صور إضافية.

## العقود المحفوظة

الأغلفة، رف الكتب الخشبي، العرض البارز والقائمة باقية. البحث والفرز والعدادات
تخص **كل النتائج** قبل تقطيع الرسم؛ لا حد لإجمالي المكتبة ولا حذف بيانات مخفية.
لا تتغير حالة القراءة أو checkpoint أو المفضلة أو التقييم. التقدم المحفوظ أعلى من
إجمالي كتالوج قديم لا يُقص أو يُعاد حفظه. الصفحات والفصول والمجلدات تبقى منفصلة.
ذاكرة التنقل محلية مؤقتة، لا تُرفع للخادم ولا تحفظ قيم الحساب في توثيق المشروع.

## التحقق

- 13 حالة جديدة، تشمل تشغيل renderer المكتبة الحقيقي ببيانات مصطنعة من 1000 عمل:
  42 بطاقة أولًا، 84 بعد المزيد، و1000 في الملخص؛ كل الأعمال تصبح قابلة للوصول.
- حالات الوظائف الجديدة الأساسية فشلت قبل تنفيذها؛ اختبار ربط renderer الإضافي
  يتحقق من العدد الفعلي ومسار البحث المحلي، لا من وجود نص API فقط.
- فحص مركّز: 27 ناجحة في المكتبة/السينما/سلامة الفلاتر.
- آخر فحص شامل بعد إصلاح النص الصغير: 3493 ناجحة، صفر فشل/تخطي/إلغاء، 73.27 ثانية.
- متصفح فعلي: أوضاع العرض الأربعة، AR/EN، بحث/مسح/فلتر فارغ/استعادة، ترتيب العنوان،
  وفتح Berserk والرجوع مع نفس البحث والترتيب. List عاد إلى نفس scrollTop في العينة.
- 12 حالة تخطيط AR بعروض CSS فعلية 320 و390 و767 (الهدف الأخير 768 مع تقريب التكبير):
  دون تجاوز أفقي، وست بطاقات محفوظة، وأهداف تبديل قرابة 43.99px بسبب تقريب المتصفح.
  أربع حالات إضافية EN عند 390، وفحص EN عند 320. فحص لقطة لاحق كشف التفاف Completed،
  ثم أُعيد القياس بعد الإصلاح: سطر واحد وشارة داخل الزر. ليست اختبارات Dynamic Type/iPhone.
- أعيدت العربية واللون المخصص الفاتح ووضع الرف؛ لا حفظ قراءة أو مراجعة أثناء الفحص.
- cache v706 والأصول المعدلة متزامنة مع `ios-web` و`ios/App/App/public` دون تحضير بيلد.

الأدلة المحلية: `artifacts/library-flow-20261111/` في مساحة العمل، خارج المستودع.
تتضمن سجلات الاختبارات وصور Lorefy وملفات التخطيط؛ لا لقطة حساب Lootd خاصة منشورة.

## المتبقي وحدود القياس

هذه ميزانية رسم واختبارات سلوك، وليست نسبة تسارع كاملة أو ضمان انعدام التأخير.
بيانات الأعمال البعيدة والصور واستعادة المراجع تحتاج الشبكة ومصادرها. عند تعذر
استعادة مرجع تظل حالة الاستعادة؛ تشخيص خدمة الاستعادة وإعادة المحاولة الأوسع مستقل.
لا تزال حسابات مشتركة في App خارج المكتبة، وكلفة تحميل الكتالوج الأول، وذاكرة
تصفح دفعات كثيرة، وINP/CLS/LCP وWKWebView على الجهاز تحتاج قياسًا مخصصًا.
